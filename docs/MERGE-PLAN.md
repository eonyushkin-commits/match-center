# Объединение «Матч-центр Теннис» и «Матч-центр» (футбол) в одно приложение

Составлен: 16.11.2026. Статус: этапы 0–3 выполнены 16.11.2026, следующий — этап 4.
Исходники: `../../match-center-tennis` (1.0.9, основа) и `../../match-center-english-football` (2.4.0).

## 1. Цель и границы

Одно приложение Electron с переключателем «Теннис / Футбол»: один установщик, один релиз,
одно окно, один набор общих настроек.

В объём входит: перенос футбола на теннисную базу, переключатель, раздельные настройки
по видам спорта, перенос настроек из обеих старых установок, переход старых установок на новую.

В объём не входит: браузерный режим футбола (`player.html`, `player.js`, `opened.mjs`) —
решение пользователя 16.11.2026, как и в теннисе; общий экран «оба вида спорта сразу», третий вид спорта. Граница делается так, чтобы третий
вид добавлялся папкой, но сам он не проектируется.

## 2. Исходное состояние (факты на 16.11.2026)

  42 коммита, в футболе 3 — все про плеер VK в отдельном окне, в теннисе он уже есть.
  История тенниса содержит историю футбола до точки ветвления.
- Уже одинаково или почти одинаково: `streams.mjs`, `vk-api.mjs`, `page-reader.mjs`,
  `server.mjs`, `settings.mjs`, `feed.mjs`, `shape.mjs`, плеер и его preload, `aspect.cjs`,
  `player-audio.cjs`, скрипты запуска и smoke.
- Спорт вшит в теннисный код в этих местах:

| Место | Что завязано на теннис |

| `core/match.mjs` | `norm` (э→е, диакритика), `parsePair` (пары через «/»), латиница; в футболе — список общих слов клубов (`GENERIC`) |

  чисел: общий список избранного невозможен.
- Не проверялось при составлении плана: тесты в обоих проектах не запускались; `web/app.js`
  и `main.cjs` просмотрены выборочно, не целиком.

## 3. Целевое устройство

```
src/core/            общее: настройки, опрос VK, лента, сервер, уведомления, диагностика, кэш
src/sports/tennis/   source.mjs (ESPN), day.mjs, match.mjs, defaults.json, players.json, tournaments.json
src/sports/football/ source.mjs (FotMob), day.mjs, match.mjs, defaults.json
src/web/             общий каркас страницы
src/web/sports/      tennis.mjs, football.mjs — строка матча, шапка раздела, тексты
src/electron/        без изменений по составу
```

Описание вида спорта (`src/sports/<id>/index.mjs`):

```js
export default {
  id: 'tennis', label: 'Теннис', sourceName: 'ESPN',
  defaults,                       // каналы, турниры/разряды, написания
  imageHosts: ['https://a.espncdn.com'],
  texts: { leagues: 'разрядов', favorites: 'избранных игроков' },   // слова для отчёта
  createSource({ fetchImpl, nodeFetch }),   // → { day(date, query), refresh(), health() }
  dayQuery(settings, tz),         // что спрашивать у источника: у тенниса — туры, у футбола — пояс
  buildDay({ data, date, tz, settings, snapshot, now }),
  health(source),                 // → [{ name, okAt, errorAt, error }] — для отчёта
  parseTitle(title),              // → { teams, doubles } | null — для vk-items
  leagueCatalog: null,            // у футбола — список турниров FotMob для добавления по номеру
};
```

Так сделано на этапе 1 (кроме `leagueCatalog` — он появится с футболом). Источник остаётся
«сырым» (`createEspn`), а `dayQuery` и `health` приводят его к общему виду: так тесты
источника не пришлось менять. Список видов — `src/sports/index.mjs`, первый — по умолчанию.

Общая форма матча, на которую опираются лента, уведомления и фильтры страницы:
`id, utcTime, timeKnown, started, finished, cancelled, liveTime, reason, favorite, remind,
streams, home/away: { id, ids, name }`. Всё остальное (сеты, посев, флаги, счёт голами,
логотипы) — поля вида спорта, их читает только `web/sports/<id>.mjs`.

Что остаётся раздельным намеренно: `norm`, `nameScore` и разбор заголовков. Правила
сопоставления у тенниса и футбола разные, и объединение их в одну функцию — главный источник
возможных регрессий. Общими делаются только `dice`, `bigrams` и каркас `matchStreams`.

Опрос VK — по одному `createStreamPoller` на вид спорта, каждый со своим списком каналов
и своим `parseTitle`. Работает только опрос выбранного вида; второй запускается при
переключении. Следствие: уведомление о матче невыбранного вида приходит без «смотреть: канал».

Настройки (`settings.json`, версия 2):

```
общие:      version: 2, refreshSeconds, notifications, tray, autostart,
            ui: { theme, window, filters, hideScores, leaguesByTime, trayHintShown, sport }
sports.<id>: channels, leagues, teamAliases, favorites, favoriteMatches
```

API: `GET /api/events?sport=…&date=…&tz=…`, `GET|PUT /api/settings?sport=…`,
`POST /api/refresh?sport=…`, `GET /api/leagues?sport=football`.

## 4. Решения

Пункты 1–4 — решения пользователя 16.11.2026.

1. **Имя и идентификатор.** Объединённое приложение наследует футбольное: «Матч-центр»,
   `ru.sportcenter.matchcenter`, папка `%APPDATA%\MatchCenter`, версия 3.0.0. Футбольные
   установки обновляются на месте, теннисные переходят вручную (п. 3).
2. **Репозиторий релизов.** Новый `match-center`. В футбольном репозитории выпускается
   промежуточная 2.5.0, в которой меняется только адрес обновлений; с неё установка сама
   переходит на 3.0.0.
3. **Переход с тенниса.** Последний теннисный релиз 1.1.0 показывает полосу «Теннис теперь
   в Матч-центре» со ссылкой на установщик; новое приложение при первом запуске забирает
   настройки из `%APPDATA%\TennisCenter`. **Не сейчас:** релиз выпускается только после того,
   как пользователь сам протестирует объединённое приложение и даст отдельное разрешение.
   Толкование агента: то же условие относится к футбольной 2.5.0 — она тоже переводит
   пользователей, причём автоматически. Пользователем это не подтверждено.
4. **Уведомления в футболе.** Только фактическое начало матча, как в теннисе. Напоминание
   «за 15 минут» из футбола не переносится.
5. **Опрос каналов невыбранного вида** (техническое решение агента, пользователю не
   задавалось): не опрашивать, см. раздел 3. Альтернатива — опрашивать оба всегда: вдвое
   больше запросов к VK.

| Эфиры перестают привязываться после переноса сопоставления | Правила сопоставления не объединяются; тесты обоих проектов переносятся дословно до любых правок |

| Автообновление 2.4.0 → 2.5.0 → 3.0.0 не срабатывает | Проверить на настоящей установке до публикации 3.0.0 как latest; до проверки старые репозитории не архивировать |
| Этап 1 разрастается в переписывание | Этап 1 — только перенос и интерфейс; любое изменение поведения — отдельным PR |
| FotMob изменил ответ с 14.11.2026 | Проверка формы уже есть (`shape.mjs`); настоящая проверка — в чек-листе релиза |
